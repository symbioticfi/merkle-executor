# Transaction processing

The engine is copied from vault-solver stage at `cc75494298aa3c9b4a17021564d569b811a8fd42` into `internal/vaultsolver/txmanager`. Its 33 source/unit-test files have only import-path substitutions and gofmt import ordering; `internal/vaultsolver/source.json` records source hashes and `source_test.go` verifies parity offline. Three Anvil test files additionally adapt the chain constructor. The small `merkle_bridge.go` exposes existing receipt-confirmation and owned-nonce-floor helpers to recovery; it adds no sending policy. The telemetry bridge preserves contextual logs and OpenTelemetry spans without bringing in vault-solver's application exporters. Transaction metrics use its existing names and bounded labels.

The engine owns one signed lifecycle at a time. It reads the write endpoint's mined nonce before preparation, retains that nonce through estimation/signing, and ignores pending counts for selection. It keeps a floor for canonically confirmed owned nonces. Fees use the next base fee, its exact EIP-1559 growth bound and recent block fullness. Gas is estimated against the next block; unsupported block overrides use latest-state estimates with larger headroom. New-block validity, congestion or stall evidence triggers same-nonce replacements; unavailable fee windows use bounded fallback bumps. All variants remain eligible for receipt discovery. Ambiguous sends get an exact-byte rebroadcast, with no new nonce. Pending timeout and shutdown drain are bounded. The engine never sends cancellation self-transfers.

Merkle's adapter adds business durability. The keeper persists the job before admission; the signing wrapper validates sender, chain, destination, calldata, value and signature payload, and fsyncs every signed attempt before returning it to the broadcaster. A persistence error blocks further signing and acknowledgement. Caller cancellation returns pending work while the engine continues on its process context. The next keeper tick joins that lifecycle, rather than creating another one. Even unsigned admitted work retains its job identity until the engine reports a result.

The journal stores one identity and same-nonce variants. Terminal success/revert is persisted only after the engine's canonical ancestry and descendant-depth proof, plus validation of receipt logs. An older variant's receipt can win. The result carries its exact hash, block and logs; providers use that evidence to reconcile their prepared calls. Keeper progress is persisted before acknowledgement clears the journal. A restored terminal journal also restores the owned-nonce floor.

Vault-solver integrations can rebuild fresh business work after tracking abandonment using current protocol state. A generic Merkle recipe can be repeatable and has no universal order ID/idempotency check. Consequently Merkle retains its unresolved journal when the engine abandons tracking or observes foreign nonce consumption. Restart checks every owned hash without replaying stored calldata. Neither a missing receipt, an RPC error nor a pending nonce is proof that the recipe failed. This intentional business-layer constraint prevents duplicate recipe execution and unauthorized external settlement.

Configuration follows vault-solver's `txManager` block. `maxFeeGwei` is a finite positive ceiling. Defaults: confirmations 2, broadcast timeout 5000 ms, account telemetry interval 30000 ms, fallback replacement interval 30000 ms, pending timeout 300000 ms, shutdown drain 60000 ms, late-receipt retention 600000 ms and hash capacity 1024. Merkle keeps its existing receipt `pollInterval` duration (default 2s). Pending timeout must cover at least one replacement interval; all millisecond settings must fit `time.Duration`.

`horizon` defaults: maxBlocks 6 (allowed 3–12), blockTimeMs 12000, tipFloorGwei 0.02, fullBlockTipGwei 0.1, congestedTipFloorGwei 0.2, congestedTipCapGwei 15, congestedRewardBlocks 3, congestedRewardPercentile 50, escalateAfterFullBlocks 2, stallAfterBlocks 3, gasHeadroomBps 500, fallbackGasHeadroomBps 1000. Tips must be finite, positive and ordered; windows are bounded to 64 blocks and fallback headroom to 5000 bps. Startup checks that the congested tip leaves initial base-fee headroom under the global cap. Operators moving from the previous sender replace the static fee/tip/gas fields with this block; no static-fee compatibility mode exists.

Read RPC handles simulation, fee history, receipts and confirmation headers. Write RPC handles nonce admission and broadcast. RPC error text is redacted but preserves a finite allowlist of nonce, fee/rejection and execution-revert classifications; original typed causes remain available for invalid-params fallback and revert decoding. No endpoint credentials or provider response text appear in lifecycle logs.
